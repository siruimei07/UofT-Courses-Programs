# 实现启动提示词

在本项目的下一轮对话中粘贴下方内容。技能、AGENTS.md 与参考图已保存在项目内。

---

请开始实现本项目的 V1：部署目标为 GitHub Pages 的多伦多大学 UTM 课程依赖图与专业选课推荐网页。

先阅读根目录 AGENTS.md，按工作内容加载 .agents/skills/ 下的项目技能，并查看 docs/reference/dependency-graph.png。这些文件已经准备好；本轮需要实际实现，不再停留在方案或技能准备。

范围与数据：
1. V1 覆盖当前 UTM Calendar 的全部 Courses 和 Programs，不局限于计算机专业或少量示例。来源为 https://utm.calendar.utoronto.ca/course-search 和 https://utm.calendar.utoronto.ca/program-search 及官方详情页。
2. 只考虑当前版本课程，使用单一数据快照。我每年手动维护一次，不需要历史版本切换、自动同步或定时任务。
3. V2 再加入 UTSG，UTSC 暂不考虑；架构区分校区，但不要现在采集或实现另外两个校区。
4. 保留规则原文、官方来源和更新日期。正确表达 AND/OR、分数、学分、并修、排除和许可等条件；未解析的要求显示待确认，不能假装已满足。当前页面里按入学 cohort 划分的条件需要保留。

功能与设计：
5. 参考截图实现宽幅泳道依赖图：学科分组、从左到右的依赖、曲线连线、搜索、筛选、缩放、平移、适配视图、课程详情；点课程突出先修与后续关系。
6. 用户可以选择专业，记录已完成/正在修读/计划课程，并得到有依据的课程推荐。区分专业入学和完成要求，解释推荐原因、缺失条件和可能解锁的后续课程；不把计划修读算作已经通过。
7. 默认图要可读，全目录要可搜索访问；用真实全量数据验证性能。提供键盘可用的列表替代视图和窄屏体验。
8. 优先 React + TypeScript + Vite、React Flow + ELK、静态 JSON，使用可解释的本地规则引擎。学生档案默认只存在本机。可以基于实测调整实现细节并说明理由。

执行与交付：
9. 先勘察少量真实条款，打通采集—解析—规则—图—推荐的纵向流程，再扩展到全目录；示例数据只能是中间步骤。采集需覆盖真实分页并输出完整性和解析质量报告。
10. 分阶段持续实现，合理并行独立任务；每阶段报告已完成、验证结果和剩余问题。普通可逆的本地实现不需要反复询问许可。
11. 完成有意义的规则测试、类型检查、生产构建和真实浏览器交互/视觉检查，并验证 GitHub Pages 仓库子路径。保留可复现命令、数据维护方式和已知限制。
12. 准备 GitHub Actions/Pages 发布配置。若现有上下文中有明确目标仓库与发布授权，则继续完成部署；若缺仓库归属、地址或权限，先完成本地可运行成果与可审查的部署配置，再只询问缺失信息，不猜测账号或仓库。
